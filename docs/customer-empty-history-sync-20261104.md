# 小程序历史报告清理后的列表同步

版本：mini-history-empty-sync-1；软件范围：小程序 API 的历史列表查询。

## 问题与行为

小程序“我的”先展示 `geogi_my_orders`，仅在项目接口成功时以服务器列表替换缓存。手机号下最后一条诊断被删除后，原接口返回 404，已发布的小程序把它视为同步失败，继续保存旧卡片。

修复后，已认证手机号且未指定客户筛选、名下没有诊断时，`GET /api/customer/projects` 返回 HTTP 200、`ok: true`、空 `orders` 和 `notifications`。现有小程序在下一次进入“我的”或下拉刷新时直接清空旧报告卡片与结果提醒，无需变更微信客户端包。

明确指定无归属的客户仍返回 404，直接读取被删除报告仍返回 404，未认证仍返回 401。其他手机号及同手机号下尚存的诊断继续按现有归属规则返回。接口故障不伪装为成功空列表。

本次仅修正查询语义，不新增删除动作，不修改订单、支付、退款、报告交付包或手机号账号。

## 验证

`server/tests/customer_empty_history_http_regression.js` 在本地隔离存储与随机端口执行实际 Express 路由和签名手机号鉴权，覆盖空列表、未认证、伪造会话、明确筛选越权、直接报告拒绝、多客户归属、其他客户保留，以及原版“我的”页面清空旧卡片、提醒和本地缓存。

该测试不使用生产密钥或生产客户资料，不连接飞书或支付服务。生产版本的额外 Report V2.1 路由须保留；发布时仅将本次七行查询修复叠加至已核实的在线 `src/server.js`，不得用较早整文件覆盖线上桥接能力。上线前重核完整文件摘要、备份、隔离测试和恢复路径。

## 验收

有效手机号授权下重新进入“我的”或下拉刷新，已清理的六组诊断卡片与完成提醒消失；不存在报告详情依旧不可读取。若手机授权失效，应重新授权后同步；离线或未认证状态没有服务器同步成功的保证。
